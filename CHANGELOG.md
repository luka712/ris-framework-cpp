# Changelog

## 0.1.0

First release.

- C++20 API in namespace `ris` (RAII, move-only types, exceptions) with a flat C API (`ris/ris.h`) over it, built for P/Invoke.
- SDL3 window, events and input; OpenGL ES 3.0 context through EGL (ANGLE on Windows and macOS, system EGL on Linux).
- Buffers, shaders (uniforms and uniform blocks), meshes (instancing), textures, render targets, sprite batch. Math is glm: `ris::Mat4` is `glm::mat4`, a public header-only dependency (the C API keeps plain `float[16]`).
- KTX2 textures through [ris-ktx2-cpp](https://github.com/luka712/ris-ktx2-cpp): Basis Universal data is transcoded to ASTC, then ETC2, then RGBA8.
- C API review fixes from the C# binding work: `ris_gfx_read_pixels` takes `out_size`, `ris_mesh_desc` and `ris_sampler_desc` have `struct_size` (+ `ris_mesh_desc_default`, `ris_sampler_desc_default`), explicit padding fields in `ris_sprite` and `ris_mesh_desc`, `ris_render_target_bind(NULL)` restores the viewport, string lifetimes documented.
- High level API like ris-framework-ts: `Framework` (listeners and game loop), `Scene`, `PerspectiveCamera` / `OrthographicCamera` / `OrbitCamera` and `CameraFactory`, ambient / directional / point lights, `UnlitMaterial` and `BlinnPhongMaterial` (built-in GLSL ES shaders), `Mesh` with sub meshes, `MeshFactory`, `GeometryBuilder`, `ContentManager` (textures, KTX2, OBJ/MTL meshes), the input manager and the time manager (see below), `Color`, `Rect`, and `SpriteBatch::draw` / `draw_rect`.
- The low level C++ `ris::Mesh` / `MeshDesc` are now `ris::VertexArray` / `VertexArrayDesc` so the high level `Mesh` can use the name. The C API is unchanged.
- C API: `ris_texture_set_sampler` returns a `ris_result`, `ris_set_log_level` and `ris_window_get_gl_info` take the enum types, and the `struct_size` rules are documented in `ris.h`.
- Samples: sprite_batch, unlit_mesh and blinn_phong_mesh, ported from the TypeScript and C# demos.
- PNG/JPEG/etc. loading through the stb image functions in ris-ktx2.
- Buffers like ris-framework-ts, split into a graphics API neutral layer and a backend layer (`ris/buffers.hpp` includes everything):
  - `ris/rendering/buffers/` mirrors `api/rendering/buffers` of ris-framework-ts, one header per concept and no graphics API types, headers or handles: the abstract classes `ABuffer`, `AVertexBuffer`, `AIndexBuffer` (16 or 32 bit), `AUniformBuffer` (padded to 16 bytes, `update`) and `ABufferFactory`, plus `BufferUsageFlags`, `VertexBufferLayout` (with `validate()`) / `VertexAttribute` / `VertexFormat` / `VertexStepMode` / `IndexBufferType`, and `ris::buffer_validation`, the shared rules (usage resolution, stride and size checks, index narrowing, uniform padding) that every backend reuses so errors read the same on all of them. `ris::create_default_buffer_factory()` (`ris/rendering/default_buffer_factory.hpp`) returns the factory of the backend the framework is built for; it is the only place outside a backend folder that names a backend.
  - `ris/gles/buffers/` (sources in `src/gles/buffers/`, tests in `tests/gles/buffers/`) mirrors `webgl/buffers`: `GlesVertexBuffer`, `GlesIndexBuffer`, `GlesUniformBuffer` and `GlesBufferFactory`, deriving from the abstract classes and wrapping the low level `ris::Buffer`. GL specific members live only here: `gl_handle()`, `buffer()`, `binding()`, `index_type()`, `GlesUniformBuffer::bind_base` and `ris::gles::make_vertex_array_desc`. A future backend adds `ris/<api>/buffers/` deriving from the same classes and is selected in `create_default_buffer_factory()`.
  - `ris::Mesh` holds `AVertexBuffer` / `AIndexBuffer` and creates them through the default factory. No C API changes.
  - A CTest checks that the headers in `ris/rendering/` include no backend or GL header, and every one of them is compiled on its own without the GL include path.
  - Not released yet, so there are no aliases for the earlier concrete names: `BufferBase`/`IBuffer` → `ABuffer`; `ris::VertexBuffer`, `IndexBuffer`, `UniformBuffer`, `BufferFactory` → `ris::gles::GlesVertexBuffer`, `GlesIndexBuffer`, `GlesUniformBuffer`, `GlesBufferFactory` (use `ABufferFactory` / `create_default_buffer_factory()` to stay backend independent); `ris::make_vertex_array_desc` → `ris::gles::make_vertex_array_desc`; `VertexBufferLayout::to_vertex_attribs` → `ris::gles::vertex_buffer_layout::to_vertex_attribs`.
- OpenGL ES utilities like `webgl/` of ris-framework-ts (namespace `ris::gles`, `ris/gles/gles.hpp` includes everything; one header per concept in `ris/gles/utilities/`, sources in `src/gles/utilities/`, tests in `tests/gles/`). TypeScript static classes became namespaces of free functions; GL object handles are `ris::gles::GlUint` and enums `GlEnum`, so the GL headers stay private. Mapping from ris-framework-ts `src/webgl`:
  - `utilities/WebGlConverter` → `gles_converter.hpp`; `WebGlBufferUtilities` → `GlesBufferUtilities` (`gles_buffer_utilities.hpp`, see below); `WebGlShaderUtilities` → `shader_utilities.hpp`; `webgl-program-utilities` → `program_utilities.hpp`; `WebGlTextureUtilities` → `GlesTextureUtilities` (`gles_texture_utilities.hpp`, see below); `WebGlSamplerUtilities` → `sampler_utilities.hpp`; `WebGlFrameBufferUtilities` → `framebuffer_utilities.hpp`; `webgl-renderbuffer-utilities` → `renderbuffer_utilities.hpp`; `webgl-blending-utilities` → `blending_utilities.hpp`; `webgl-culling-utilities` → `culling_utilities.hpp`; `webgl-filter-anisotropic-utilities` → `anisotropic_filter_utilities.hpp`; `spector-js-utilities` → `debug_label_utilities.hpp` (KHR_debug object labels instead of Spector metadata); `WebGlUtilities` → `gles_utilities.hpp`.
  - `rendering/webgl-vertex-attribute` and `webgl-vertex-buffer-layout` → `ris/gles/rendering/vertex_attribute.hpp` and `vertex_buffer_layout.hpp`. `buffers/*` → `ris/gles/buffers/` (`GlesVertexBuffer`, `GlesIndexBuffer`, `GlesUniformBuffer`, `GlesBufferFactory`), which implement the abstract buffer classes of `ris/rendering/buffers/`.
  - New: `error_utilities.hpp`, `gles_context_utilities.hpp` (`GlesContextUtilities`: extension queries), `ris/utilities/align_utilities.hpp` (`align`, `align_array`) and the enums `TextureFormat`, `SamplerFilter`, `MipMapSamplerFilter`, `SamplerAddressMode`, `SamplerCompareFunction`, `BlendOperation`, `BlendFactor`, `FrontFace`, `ShaderStage`.
  - Not ported: `WebGlRenderer`, render pipelines, lights and the shader / texture wrapper classes; these need the WebGPU-style object model, which this library does not have (`gfx`, `Texture`, `Shader`, `RenderTarget` fill that role). The graphics device, sampler, blend / primitive state, render pass, swap chain, gpu info and device features are in the graphics device entry below.
  - `graphics.cpp`, `texture.cpp` and the OpenGL ES buffers now call these utilities instead of private GL helpers. Public API, rendered output and the C API are unchanged (the five samples render identical images).
  - Small behaviour differences: GL errors read `OpenGL ES error 0x… in <what>`; out of range enum values throw `std::domain_error` instead of falling back to a default; framebuffer utilities restore the previous framebuffer binding; the `RenderTarget` colour texture uses immutable storage; `glDrawBuffers` is set for more than one colour attachment; `GL_UNPACK_ALIGNMENT` is restored after uploads; anisotropic filtering is implemented (the TypeScript version throws); buffers get a GL object label when `GL_KHR_debug` is available.
- Input like ris-framework-ts (`api/input`), on SDL3 (`ris/input.hpp` includes everything, the C API is unchanged). SDL3 is an integral part of the engine (windowing, input, time); only the rendering API is pluggable, so input has no abstract class and no backend folder:
  - `ris/input/` (sources in `src/input/`, tests in `tests/input/`) has one header per concept and no SDL or window types in any header: the concrete `ris::InputManager` (`keyboard_state`, `mouse_state`, `game_pad_state(index)`, `touch_collection`, `touch_capabilities`, `thumbstick_dead_zone`, `initialize` / `update` / `after_update` / `dispose`, `handle_event(const Event&)`, `handle_native_event(const void*)`; it tracks the per frame state and translates SDL events), `KeyboardState`, `MouseState`, `GamePadState` / `GamePadThumbSticks`, `TouchCollection` / `TouchLocation` / `TouchLocationState` / `TouchPanelCapabilities` and the enums `Key`, `MouseButton`, `GamePadButton`, `InputDeviceType`. The SDL3 gamepad, touch, keyboard and mouse API is used directly in `src/input/input_manager.cpp`; SDL stays private (a small pimpl holds the gamepad slots and finger ids).
  - Keyboard, mouse (five buttons), gamepads (SDL gamepad API, up to four, sticks / triggers / buttons, hot plug, dead zone) and touch (SDL finger events scaled to window coordinates). With no gamepad or touch device the state just reports "not connected" / empty. The manager gets every SDL event from `SdlWindowManager::addOnSdlEventListener` (`Framework` registers `handle_native_event`; touch and gamepad events have no `ris::Event`, whose C layout cannot change).
  - Test seam: the `report_key`, `report_mouse_*`, `report_game_pad_*`, `report_touch`, `report_focus_lost` and `set_touch_capabilities` functions of `InputManager` are public (documented as the platform independent way to feed the state, also for replays or custom event sources), so the state tests drive a real `InputManager` without a window, a device or an SDL event; `tests/input/test_input_manager_sdl_events.cpp` feeds synthetic `SDL_Event`s through `handle_native_event`.
  - `Event`, `EventType` and `key_mod` moved from `window.hpp` to `ris/event.hpp` (`window.hpp` is gone, `ris/ris.hpp` includes it).
  - Added compared to the first `InputManager`: touch (the contact pool, pressed / moved / released / cancelled and previous locations of the TS version), gamepads, `is_key_pressed` / `is_button_pressed` (down on this frame), `MouseButton::X1` / `X2` and more keys (`Minus`, `Equal`, `Delete`, `Insert`, `Home`, `End`, `PageUp`, `PageDown`, numpad, ...). Behaviour of keyboard, mouse, wheel and focus loss is unchanged.
  - Not ported from TS: the DOM / pointer-lock specifics and the keyboard text / IME input (the browser only), `InputDeviceType` is provided as flags but nothing reads it.
  - Not released yet, so no aliases: `ris::InputManager` keeps its name but is now declared in `ris/input/input_manager.hpp` and built from `src/input/input_manager.cpp` (`Framework::inputManager()` returns `InputManager&`); `InputManager::begin_frame()` → `update()` (the framework calls `update()` then `after_update()` every frame, and no longer passes events to `handle_event`; `handle_event(const Event&)` stays for tests and custom pumps); `MouseButton` is now `None = 0, Left = 1, Right = 2, Middle = 3, X1 = 4, X2 = 5` like TS (`Middle` and `Right` were 2 and 3 the other way round); `OrbitCamera` takes a `const InputManager&`; `src/time_input.cpp` became `src/time.cpp`.
  - A CTest additionally checks that the headers in `ris/input/` include no SDL, window, GL or backend header, and each is compiled on its own with only the public include path. Rendered output of the five samples is unchanged.
- Time like ris-framework-ts (`api/time`: `GameTime`, `ITimeManager` / `TimeManager`), on the SDL3 time API (`ris/time.hpp` includes everything, the C API is unchanged). SDL3 is an integral part of the engine (windowing, input, time); only the rendering API is pluggable, so time has no abstract class and no backend folder:
  - `ris/time/` (sources in `src/time/`, tests in `tests/time/`) has one header per concept and no SDL types in any header: the concrete `ris::TimeManager` (all the per frame logic: delta, elapsed time, time scale, pause, fixed step accumulator, frame limiting, delta smoothing, the frame rate and the deterministic mode), `GameTime`, `DateTime`, the `ris::time_units` helpers, `FrameRateCounter`, `Stopwatch`, `Timer`, the `ris::system_clock` functions (`ticks()`, `ticks_per_second()`, `now_ns()`, `delay_ns()`, `delay_precise_ns()`, `unix_time_ns()`, `to_date_time()`, `from_date_time()`, `current_date_time()`) and `ris::ClockSource`.
  - The SDL3 time API is used directly in `src/time/system_clock.cpp` (`SDL_GetPerformanceCounter` / `SDL_GetPerformanceFrequency`, `SDL_DelayNS` / `SDL_DelayPrecise`, `SDL_GetCurrentTime`, `SDL_TimeToDateTime` / `SDL_DateTimeToTime`). SDL stays private.
  - `ris::ClockSource` (a tick counter function, its frequency and an optional precise delay function) is the test seam: `TimeManager()` and `Stopwatch()` use `ClockSource::system()`, and `TimeManager(ClockSource)` / `Stopwatch(ClockSource)` let a unit test move time by hand without sleeping (`tests/time/fake_clock.hpp`).
  - Added compared to the first `TimeManager`: time scale, pause / resume, a fixed time step (`consume_fixed_step`, `fixed_step_alpha`, capped steps per frame, new `Framework::addOnFixedUpdateListener`), frame limiting (`target_frames_per_second`, slept with `SDL_DelayPrecise`), delta smoothing, a running slowly flag, an FPS counter, `Stopwatch`, a `Timer` that is driven by game time (so it respects scale and pause and always fires on the game thread), and wall clock / date conversion (UTC or local). The new `FrameworkConfiguration::target_frames_per_second` and `fixed_time_step_ms` default to off, so frame pacing is unchanged. The fields of `GameTime` and their values are unchanged.
  - Not released yet, so no aliases: `ris::TimeManager` keeps its name but is now declared in `ris/time/time_manager.hpp` and built from `src/time/time_manager.cpp` (`Framework::timeManager()` returns `TimeManager&`); the old fixed step clock mode is now `set_deterministic_step_ms()` (used by the framework when `max_frames` is set); `ris::time_seconds()` / `ris::sleep_ms()` and the C functions `ris_get_time_seconds` / `ris_sleep_ms` keep their signatures and now use `ris::system_clock`; `Camera` includes `ris/time/game_time.hpp`; `src/time.cpp` was removed.
  - Not ported from TS: `Date.now` based timing (SDL's monotonic counter is used instead). `SDL_AddTimerNS` is not used because its callbacks run on another thread; `Timer` is polled by the manager instead.
  - A CTest additionally checks that the headers in `ris/time/` include no SDL, window, GL or backend header (it covers `ris/rendering/`, `ris/input/` and `ris/time/`). Rendered output of the five samples is unchanged.
- Framework listeners and naming (like `IFramework` of ris-framework-ts):
  - The framework methods are camelCase. Not released yet, so no aliases: `window_manager()` → `windowManager()`, `input_manager()` → `inputManager()`, `time_manager()` → `timeManager()`, `camera_factory()` → `cameraFactory()`, `material_factory()` → `materialFactory()`, `mesh_factory()` → `meshFactory()`, `sprite_batch()` → `spriteBatch()`, `add_on_load_content_listener` → `addOnLoadContentListener`, `add_on_initialized_listener` → `addOnInitializedListener`, `add_on_update_listener` → `addOnUpdateListener`, `add_on_fixed_update_listener` → `addOnFixedUpdateListener`, `add_on_render_listener` → `addOnRenderListener`, and `remove_on_*_listener` → `removeOn*Listener`. `content()`, `configuration()`, `renderer()`, `initialize()` and `quit()` keep their names. `Renderer::add_on_resized_listener` / `remove_on_resized_listener` are unchanged (not a framework method).
  - `ris::Framework` is a single concrete class that owns the window, renderer, input, time and factories and runs the loop. `CameraFactory` and `ContentManager` take a `Framework&`.
  - Listener callbacks are stored in a plain `std::map<uint32_t, std::function<...>>` per kind (so they run in registration order) instead of vectors of pairs. The ids are `uint32_t` and come from a static `uint32_t` counter per kind (1, 2, 3, ..., shared by all frameworks, 0 is never used). Adding or removing a listener while listeners run is safe (the dispatch loops over a copy): a listener added meanwhile first runs on the next dispatch and a removed one is not called any more.
  - A callback takes the `Framework&` as its first argument: each `add...Listener` takes a `std::function<void(Framework&, ...)>`.
  - `ContentManager::loadTexture2D` and `load_ktx2` return a non-owning `Texture*` instead of `std::shared_ptr<Texture>`. The content manager owns the textures and frees them when the framework is destroyed. `UnlitMaterialDescriptor` / `BlinnPhongMaterialDescriptor::diffuse_texture` and the materials' `diffuse_texture` are `Texture*` too.
  - `Renderer::clear_color` (public member) is now private with `Color getClearColor() const` and `void setClearColor(Color)`.
- Texture factory like ris-framework-ts (`ITextureFactory`): the abstract `ATextureFactory` (`ris/rendering/texture/a_texture_factory.hpp`, no GL types) and the OpenGL ES implementation `GlesTextureFactory` (`ris/gles/texture/gles_texture_factory.hpp`, source `src/gles/texture/gles_texture_factory.cpp`, tests `tests/gles/texture/`), plus `TextureUsage` and `TextureDescriptor` and `ris::create_default_texture_factory()`. `Framework::textureFactory()` returns it.
  - `createEmpty(width, height, defaultColor, textureUsage, textureFormat, label)` and `create(width, height, data, channels, label, usage, textureFormat, generateMipMaps)` build RGBA8 textures (`channels` must be 4, `data` is a `std::span<const uint8_t>`); `createFromKtx2(ktxTexture2*, TextureDescriptor)` uploads a loaded KTX2 file (transcoding Basis data to ASTC, then ETC2, then RGBA8 when the descriptor format is `Undefined`; the previous behaviour). All three return a `std::unique_ptr<Texture>`: the caller owns the texture. `TextureDescriptor` has `textureFormat`, `textureUsage`, `label` and `generateMipmaps` (the TS `width`, `height`, `data` and `blockSize` are read from the KTX2 object).
  - The GL ES backend ignores `TextureUsage` except that `StorageBinding` throws `std::domain_error`. Differences to TS: `createEmpty` without a colour is zero filled (transparent black), `create` with empty data throws, BC7 / BC3 are not offered.
  - The KTX2 upload code (VkFormat mapping, transcoding, `glTexStorage2D` / sub image upload) moved from `src/texture.cpp` into `GlesTextureFactory::createFromKtx2`; `Texture::from_ktx2_memory` calls it. Rendered output of the five samples is unchanged. Not released yet, so no aliases. The returned class is still the concrete `ris::Texture` (the neutral header only forward declares it), to be replaced when an abstract texture class exists.
- Errors are standard exceptions instead of `ris::Error` / `ris::Result` (both removed, along with `ris::detail::throw_error`): `std::invalid_argument` (bad arguments or call order), `std::out_of_range` (index or range outside its object), `std::domain_error` (unsupported format, usage or feature), `std::logic_error` (no `ris::Window` yet), `std::ios_base::failure` (a file could not be read or written) and `std::runtime_error` (SDL, EGL, OpenGL ES, shader and KTX2 failures). Messages are unchanged. `ris.h` is unchanged: the C API maps them to `RIS_ERROR_INVALID_ARGUMENT` (`invalid_argument`, `out_of_range`), `RIS_ERROR_UNSUPPORTED`, `RIS_ERROR_NOT_INITIALIZED`, `RIS_ERROR_IO`, `RIS_ERROR_OUT_OF_MEMORY` (`bad_alloc`) and `RIS_ERROR_PLATFORM` (any other exception), so shader compile and KTX2 failures report `RIS_ERROR_PLATFORM` instead of `RIS_ERROR_COMPILE` / `RIS_ERROR_KTX` (the message is still in `ris_get_last_error()`).
- Graphics device like ris-framework-ts (`IGraphicsDevice`): the abstract `AGraphicsDevice` (`ris/rendering/a_graphics_device.hpp`, no GL types, doc comments translated from the TypeScript) and the OpenGL ES implementation `GlesGraphicsDevice` (`ris/gles/gles_graphics_device.hpp`, source `src/gles/gles_graphics_device.cpp`, tests `tests/gles/graphics_device/`). `Framework::graphicsDevice()` returns it; it is created (`ris::create_default_graphics_device()`, `ris/rendering/default_graphics_device.hpp`, the only file that names the backend) and initialised right after the window and the texture factory, and `frameEnd()` is called once per frame after the buffers are swapped. `GraphicsDeviceDescriptor::samplerFilteringPreset` comes from `FrameworkConfiguration::textureFiltering`. Rendered output of the five samples is unchanged and the C API is unchanged.
  - `AGraphicsDevice`: `getGpuInfo()`, `getFeatures()`, `getDefaultTextureSampler()`, `getDefaultBlendState()`, `getDefaultPrimitiveState()` (the TS readonly properties), `initialize()`, `setupDebugCallback()`, `frameEnd()`, `createSampler()`, `createPrimitiveState()`, `createRenderPass()`, `createSwapChain(Window&, ...)` (the TS `window: any` is the existing `ris::Window`), `pushDebugGroup()` and `popDebugGroup()`, plus `createBlendState()` (from the TS abstract base class). The TS `IDisposable` is the virtual destructor; there is no `dispose()`.
  - Graphics API neutral types in `ris/rendering/`, one header each: abstract classes `ASampler`, `ABlendState`, `APrimitiveState`, `ARenderPass`, `ASwapChain`, `AGraphicsDeviceFeatures` and `AGpuInfo` (see the GPU info entry below); plain data `RenderingBackend`, `GraphicsDeviceDescriptor`, `SamplerDescriptor`, `BlendStateDescriptor` / `BlendComponentDescriptor`, `PrimitiveStateDescriptor`, `PrimitiveTopology`, `RenderPassDescriptor` / `RenderPassColorAttachment` / `RenderPassDepthStencilAttachment`, `LoadAction`, `StoreAction`, `SwapChainDescriptor`, `SurfacePresentMode`. `CullMode` (was in `graphics.hpp`) and `TextureFilteringPreset` (was in `framework.hpp`) moved to neutral headers; the old headers include them, so existing code compiles unchanged.
  - OpenGL ES classes: `GlesGraphicsDevice`, `GlesGraphicsDeviceFeatures`, `GlesSampler` (GL sampler object, `bind(unit)`), `GlesBlendState` and `GlesPrimitiveState` (`apply()`), `GlesRenderPass` (framebuffer object or the window's default framebuffer, `beginPass()` clears and sets the viewport, `endPass()` invalidates `StoreAction::Discard` attachments) and `GlesSwapChain` (`present()` swaps the window's buffers, the present mode sets the vsync). `GpuInfo` comes from the GL strings and the features from the extensions; `setupDebugCallback()` and the debug groups use `GL_KHR_debug` (driver messages go to the log, the groups use `glPushDebugGroup`, see below). `convert_primitive_topology` was added to the converter.
  - Ownership: the objects created by the device (`createSampler`, `createBlendState`, `createPrimitiveState`, `createRenderPass`, `createSwapChain`) are caller owned raw pointers (like `ATextureFactory`); the default sampler, blend state and primitive state are owned by the device and returned as const references. Free the created objects before the device, the device before the window.
  - Differences to TS: `ClampToBorder` clamps to the edge; `SamplerDescriptor` has `compareFunction` and `maxAnisotropy` (the TS sampler does not); a swap chain always has the size of the window (`resize` only validates, the descriptor size is ignored) and `Mailbox` behaves like `Fifo`; render passes have no multisample resolve and no depth textures (the depth and stencil buffer is a render buffer, or the window's own), no texture views, `LoadAction::Undefined` loads; `BlendStateDescriptor` has no colour write mask; `frameEnd()` does nothing for OpenGL ES; underlying backend (ANGLE's) is not reported.
- `AGpuInfo` and `GlesGpuInfo`, like the other abstract / backend pairs. `ris/rendering/a_gpu_info.hpp` mirrors `IGPUInfo` of ris-framework-ts with getters: `getName()`, `getVendor()`, `getApiVersion()`, `getApi()`, `getUnderlyingBackend()` and `getSupportedCompressedTextureFormats()`. `ris/gles/gles_gpu_info.hpp` (`src/gles/gles_gpu_info.cpp`) fills it from `glGetString` once in the constructor: it needs a current context (`std::logic_error` without one), the unmasked vendor / renderer is not queried (`WEBGL_debug_renderer_info` has no GL ES counterpart), the underlying backend is `OpenGLES` when `GL_VERSION` or `GL_RENDERER` contain "OpenGL ES", else `Default` (the API below ANGLE is not reported through GL; detecting Direct3D, Vulkan and Metal is still a TODO) and the compressed formats are one representative format per supported family (ASTC, S3TC, ETC2, BC; PVRTC has no `TextureFormat` yet). `AGraphicsDevice::getGpuInfo()` returns `const AGpuInfo&`, owned by the device; `GlesGraphicsDevice` creates the `GlesGpuInfo` (and the features) in `initialize()`, so `getGpuInfo()` / `getFeatures()` throw `std::logic_error` before it.
  - Removed: the plain struct `ris::GpuInfo` (`ris/rendering/gpu_info.hpp`). Its fields are the getters above (`name` → `getName()`, `vendor` → `getVendor()`, `api_version` → `getApiVersion()`, ...). The C API is unchanged.
- `ATexture2D` like `ITexture2D` of ris-framework-ts, with the OpenGL ES implementation `GlesTexture2D`:
  - Graphics API neutral headers (`ris/rendering/texture/`, `ris/content/`, `ris/data/`): `ATexture2D`, `ATextureView`, `TextureViewDescriptor`, `TextureViewDimension`, `AContent` and `State` (`Created`, `Initialized`, `Disposing`, `Disposed`). `ATexture2D` has the getters `getDefaultTextureView()`, `getTextureUsage()`, `getTextureFormat()`, `getTextureViewFormat()`, `getId()`, `getHandle()`, `getLabel()`, `getTextureState()`, `getSize()` (rough byte count of all mip levels, compressed formats by block size), `getWidth()`, `getHeight()`, `getMipLevels()`, plus `createView()`, `initialize()` and `addOnDisposedListener()` / `removeOnDisposedListener()`.
  - OpenGL ES classes `GlesTexture2D` (`ris/gles/texture/gles_texture2d.hpp`) and `GlesTextureView` (`gles_texture_view.hpp`). `GlesTexture2D` is movable (the moved-from texture is `Disposed` and raises no event).
  - `ATextureFactory::createEmpty()`, `create()` and `createFromKtx2()` now return `ATexture2D*` (caller owned, was the concrete texture), and `RenderPassColorAttachment::texture` is an `ATexture2D*`. `ris::Texture` is now an alias of `ris::gles::GlesTexture2D`, so the low level API (`from_rgba8`, `from_image_file`, `from_ktx2_memory`, `set_sampler`, `bind`), the C API and the samples are unchanged. `src/texture.cpp` is gone, its code moved to `src/gles/texture/gles_texture2d.cpp`.
  - Ownership: a texture owns its default view; views from `createView()` are owned by the caller and must be freed before the texture. Disposing is RAII: `IContent` / `IDisposable` became the virtual destructor of `AContent` / `ATexture2D`, and the disposed listeners are called from the destructor of the implementation.
  - Differences to TS: `addOnDisposedListener()` returns a `uint32_t` id for `removeOnDisposedListener(id)` (a C++ lambda cannot be compared); `dispose()` is part of `ATexture2D` (see the `GlesTexture2D` entry below); `createView()` accepts only 2D views of the texture's view format (`std::invalid_argument` for another dimension, `std::domain_error` for another format); `getHandle()` is a `uint64_t` (the GL texture name on OpenGL ES); a texture from a factory is already `Initialized`, `initialize()` only exists for implementations that are created first and set up later.
- `GlesTextureUtilities` (`ris/gles/utilities/gles_texture_utilities.hpp`, reached through `GlesUtilities::texture()` like `GlesUtilities::context()`) replaces the free functions of the namespace `ris::gles::texture_utilities`, with the same behaviour: `createTexture2D()` (levels as `std::span`, or one pixel block; immutable storage; generated mip maps), `createCompressedTexture2D()` (immutable storage for block aligned sizes, otherwise sizes rounded up to whole blocks), `fullMipCount()` and `deleteTexture()`. Name mapping: `create_texture_2d` → `createTexture2D`, `create_compressed_texture_2d` → `createCompressedTexture2D`, `full_mip_count` → `fullMipCount`, `delete_texture` → `deleteTexture`, `texture_utilities::MipLevelData` → `GlesTextureUtilities::MipLevelData`. `GlesTexture2D` and `Texture` creation go through it. Like the TypeScript version, an anisotropy above 1 throws `std::runtime_error("Not implemented yet.")` in both functions (anisotropic filtering is a sampler setting, `SamplerDescriptor::maxAnisotropy`). Tests are in `tests/gles/utilities/test_gles_texture_utilities.cpp`.
- `GlesBufferUtilities` (`ris/gles/utilities/gles_buffer_utilities.hpp`, reached through `GlesUtilities::buffer()`) replaces the free functions of the namespace `ris::gles::buffer_utilities`, with the same behaviour: `createBuffer()`, `createVertexBuffer()`, `createIndexBuffer()` (16 / 32 bit data or a byte size; filled through `GL_COPY_WRITE_BUFFER`, so a bound vertex array keeps its index buffer), `createUniformBuffer()` (floats, raw bytes or a byte size), `updateBuffer()`, `updateVertexBuffer()` and `deleteBuffer()`; the usage conversion stays `converter::convert_buffer_usage`. Name mapping: `create_vertex_buffer` → `createVertexBuffer` and so on, `delete_buffer` → `deleteBuffer`. New: `updateVertexBuffer(buffer, data, destOffset, srcOffset, srcLength)` takes the source range in floats like `bufferSubData` with a typed array (`destOffset` in bytes) and throws `std::out_of_range` for a range outside `data`; `createBuffer()` throws `std::runtime_error("Failed to create vertex buffer.")` (index / uniform) if no buffer name is generated. `ris::Buffer` (and with it the Gles vertex, index and uniform buffers) creates and updates through it. Tests: `tests/gles/utilities/test_gles_buffer_utilities.cpp`.
- `GlesTexture2D` follows `WebGlTexture2D`: construct from a `TextureDescriptor` (now with `width`, `height`, `data` (one span per mip level) and `blockWidth` / `blockHeight`), then call `initialize()`, which creates the GL texture through `GlesUtilities::texture()` (compressed or uncompressed, anisotropy 0), sets the default sampler, and computes `getSize()` / `getMipLevels()` per level with `TextureUtilities::getVRamSize` (halving, minimum 1). It throws `std::logic_error` "Texture is already initialized." / "Texture is already disposed.". `dispose()` is public (`ATexture2D::dispose()`), idempotent and iterates a copy of the listeners, so a listener may remove itself. `getGlTexture()` returns the GL handle. `GlesTexture2D::getOrCreateDefault(Framework&)` / `disposeDefault(Framework&)` give a 1x1 white texture per framework (a static `std::map<Framework*, std::unique_ptr<GlesTexture2D>>`), disposed by `Framework::~Framework`. New neutral `ris/rendering/texture/texture_utilities.hpp` (`TextureUtilities`: `isCompressedTextureFormat`, `mipLevels`, `getVRamSize`) that the converter and `GlesTextureUtilities::fullMipCount` reuse. Differences to TS: the preferred texture format is `Rgba8Unorm` (the renderer has no accessor for it), sizes are `int32_t` instead of vectors, and `createFromKtx2` goes through the descriptor too (see the texture factory entry below). `Texture::from_rgba8` and the factory go through the descriptor and `initialize()`; the C API is unchanged. Tests are in `tests/gles/texture/` and `tests/rendering/texture/`.
- `GlesTextureFactory` follows `WebGlTextureFactory` of ris-framework-ts (`ATextureFactory` documents the contract; all three methods return `GlesTexture2D*`, caller owned). `GlesTextureFactory(Framework&)` takes the GPU features from the framework's graphics device, the default constructor queries the current GL context (for the C API and window-only code). `createFromKtx2` picks the transcode target BC7, ASTC 4x4, BC3 (S3TC), ETC2 in that order through `AGraphicsDeviceFeatures`, honours a format in the descriptor (`std::domain_error` when the GPU lacks it), keeps RGBA8 files as they are, and builds a `TextureDescriptor` with one span per mip level, then `GlesTexture2D` and `initialize()`; the label and usage are passed through. `create()` has the TS defaults (`channels` 4, `Rgba8Unorm`, `CopyDst | TextureBinding`, `useMipMaps` false) and the TS messages ("Data must not be null.", "width and height must be greater than 0.", "channels must be greater than 0."); `createEmpty()` has `useMipmap`, and no colour or transparent black allocates without an upload. New in `TextureUtilities`: `getBlockWidth` / `getBlockHeight`, `convertTextureFormatToKtxTranscodeFormat`, `convertKtxTranscodeFormatToVkFormat`, `convertVkFormatToTextureFormat`. Differences to TS: `createEmpty` with a colour writes that colour (the TS fast path also turns black into transparent), formats `TextureFormat` cannot describe (and storage usage, cube maps, arrays, 3D) throw `std::domain_error`, there is no RGBA32 fallback when the GPU supports no compressed format, and `create()` still checks the data size so no out-of-bounds read can happen. Tests in `tests/gles/texture/`.
- `GlesGraphicsDevice::pushDebugGroup(groupName)` / `popDebugGroup()` call `glPushDebugGroup` / `glPopDebugGroup` (OpenGL ES 3.2). `ris/rendering/default_texture_factory.hpp` and `create_default_texture_factory()` are removed: `Framework` creates a `gles::GlesTextureFactory` itself (`Framework::textureFactory()`), and `debug_label_utilities.hpp` is now `gles_debug_utilities.hpp`.
- Framework C API in `ris/ris.h` (section "Framework"), a pure C wrapper over `ris::Framework` for C# and other languages, built up only as far as the `sprite_batch_c_api` sample needs; additive, no existing symbol changed. Naming: a function that wraps a C++ method is `ris_` + the method name. Added: `FrameworkConfiguration` (`title`, `backBufferWidth`, `backBufferHeight`, `textureFiltering`, in its own C header `ris/framework_configuration.h`, included by `ris.h`), the one configuration of both the C API and the C++ `ris::Framework` (it replaces `ris::FrameworkConfiguration`; the defaults come from `ris_createFrameworkConfiguration`), and `TextureFilteringPreset`, the one filtering enum (it replaces `ris::TextureFilteringPreset`, whose header is removed), the handles `ris_framework` and `ris_Renderer`, the callback `ris_frameworkCallback(framework, userData)` (cdecl), and `ris_createFrameworkConfiguration`, `ris_createFramework`, `ris_destroyFramework`, `ris_addOnLoadContentListener`, `ris_addOnRenderListener`, `ris_initialize`, `ris_quit`, `ris_spriteBatch`, `ris_renderer`, `ris_setClearColor`. Tests in `tests/test_window.cpp`.
- `risColor` (own C header `ris/data.h`, included by `ris.h`) and `ris_lightPinkColor()`, which returns `ris::Color::lightPink()`.
- Sample `sprite_batch_c_api` (`ris_sample_sprite_batch_c_api`, `samples/sprite_batch_c_api/main.c`): the `sprite_batch` sample in plain C against `ris/ris.h` only, through the Framework C API (load content and render listeners with `userData`). The C++ sample is unchanged.
- `WindowManager` (`ris/window_manager.hpp`, one concrete class, no abstract base) like `IWindowManager` of ris-framework-cs, which creates and owns the SDL3 window and the OpenGL ES context (plain members, no pimpl) and runs the event loop. It does no input: the `InputManager` gets the SDL events through `WindowManager::addOnSdlEventListener` (registered by `Framework`; Escape closing the framework loop is checked by `Framework` through the keyboard state). `Framework::windowManager()` returns the interface. The `ris::Window` class (`ris/window.hpp`) and the old `ris::WindowManager` class are gone: `WindowDesc`, `WindowFlags` and `AngleBackend` live in `ris/window_manager.hpp`. Not released yet, so no aliases: `Window::poll_event`, `ris::input::key_down` / `mouse_state`, `gl_info`, `has_gl_extension` and the other `Window` extras are removed from the C++ API (use `InputManager`, `GlesUtilities::context()` and, for custom pumps, SDL itself); `Renderer::backend_name()` / `device_name()` are removed (the window manager logs the GL renderer, version and ANGLE backend when it starts). The C API (`ris_window_*`, `ris_input_*`) is unchanged and now talks to SDL directly in `src/c_api.cpp`.
