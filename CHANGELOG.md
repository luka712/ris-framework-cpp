# Changelog

## 0.1.0

First release.

- C++20 API in namespace `ris` (RAII, move-only types, exceptions) with a flat C API (`ris/ris.h`) over it, built for P/Invoke.
- SDL3 window, events and input; OpenGL ES 3.0 context through EGL (ANGLE on Windows and macOS, system EGL on Linux).
- Buffers, shaders (uniforms and uniform blocks), meshes (instancing), textures, render targets, sprite batch. Math is glm: `ris::Mat4` is `glm::mat4`, a public header-only dependency (the C API keeps plain `float[16]`).
- KTX2 textures through [ris-ktx2-cpp](https://github.com/luka712/ris-ktx2-cpp): Basis Universal data is transcoded to ASTC, then ETC2, then RGBA8.
- C API review fixes from the C# binding work: `ris_gfx_read_pixels` takes `out_size`, `ris_mesh_desc` and `ris_sampler_desc` have `struct_size` (+ `ris_mesh_desc_default`, `ris_sampler_desc_default`), explicit padding fields in `ris_sprite` and `ris_mesh_desc`, `ris_render_target_bind(NULL)` restores the viewport, string lifetimes documented.
- High level API like ris-framework-ts: `Framework` (listeners and game loop), `Scene`, `PerspectiveCamera` / `OrthographicCamera` / `OrbitCamera` and `CameraFactory`, ambient / directional / point lights, `UnlitMaterial` and `BlinnPhongMaterial` (built-in GLSL ES shaders), `Mesh` with sub meshes, `MeshFactory`, `GeometryBuilder`, `ContentManager` (textures, KTX2, OBJ/MTL meshes), `InputManager`, `TimeManager`, `Color`, `Rect`, and `SpriteBatch::draw` / `draw_rect`.
- The low level C++ `ris::Mesh` / `MeshDesc` are now `ris::VertexArray` / `VertexArrayDesc` so the high level `Mesh` can use the name. The C API is unchanged.
- C API: `ris_texture_set_sampler` returns a `ris_result`, `ris_set_log_level` and `ris_window_get_gl_info` take the enum types, and the `struct_size` rules are documented in `ris.h`.
- Samples: sprite_batch, unlit_mesh and blinn_phong_mesh, ported from the TypeScript and C# demos.
- Samples: ktx2_quad and ktx2_compare (KTX2 textures as ASTC, ETC2 and RGBA8).
- PNG/JPEG/etc. loading through the stb image functions in ris-ktx2.
- Buffers like ris-framework-ts, split into a graphics API neutral layer and a backend layer (`ris/buffers.hpp` includes everything):
  - `ris/rendering/buffers/` mirrors `api/rendering/buffers` of ris-framework-ts, one header per concept and no graphics API types, headers or handles: the abstract classes `ABuffer`, `AVertexBuffer`, `AIndexBuffer` (16 or 32 bit), `AUniformBuffer` (padded to 16 bytes, `update`) and `ABufferFactory`, plus `BufferUsageFlags`, `VertexBufferLayout` (with `validate()`) / `VertexAttribute` / `VertexFormat` / `VertexStepMode` / `IndexBufferType`, and `ris::buffer_validation`, the shared rules (usage resolution, stride and size checks, index narrowing, uniform padding) that every backend reuses so errors read the same on all of them. `ris::create_default_buffer_factory()` (`ris/rendering/default_buffer_factory.hpp`) returns the factory of the backend the framework is built for; it is the only place outside a backend folder that names a backend.
  - `ris/gles/buffers/` (sources in `src/gles/buffers/`, tests in `tests/gles/buffers/`) mirrors `webgl/buffers`: `GlesVertexBuffer`, `GlesIndexBuffer`, `GlesUniformBuffer` and `GlesBufferFactory`, deriving from the abstract classes and wrapping the low level `ris::Buffer`. GL specific members live only here: `gl_handle()`, `buffer()`, `binding()`, `index_type()`, `GlesUniformBuffer::bind_base` and `ris::gles::make_vertex_array_desc`. A future backend adds `ris/<api>/buffers/` deriving from the same classes and is selected in `create_default_buffer_factory()`.
  - `ris::Mesh` holds `AVertexBuffer` / `AIndexBuffer` and creates them through the default factory. No C API changes.
  - A CTest checks that the headers in `ris/rendering/` include no backend or GL header, and every one of them is compiled on its own without the GL include path.
  - Not released yet, so there are no aliases for the earlier concrete names: `BufferBase`/`IBuffer` → `ABuffer`; `ris::VertexBuffer`, `IndexBuffer`, `UniformBuffer`, `BufferFactory` → `ris::gles::GlesVertexBuffer`, `GlesIndexBuffer`, `GlesUniformBuffer`, `GlesBufferFactory` (use `ABufferFactory` / `create_default_buffer_factory()` to stay backend independent); `ris::make_vertex_array_desc` → `ris::gles::make_vertex_array_desc`; `VertexBufferLayout::to_vertex_attribs` → `ris::gles::vertex_buffer_layout::to_vertex_attribs`.
- OpenGL ES utilities like `webgl/` of ris-framework-ts (namespace `ris::gles`, `ris/gles/gles.hpp` includes everything; one header per concept in `ris/gles/utilities/`, sources in `src/gles/utilities/`, tests in `tests/gles/`). TypeScript static classes became namespaces of free functions; GL object handles are `ris::gles::GlUint` and enums `GlEnum`, so the GL headers stay private. Mapping from ris-framework-ts `src/webgl`:
  - `utilities/WebGlConverter` → `gles_converter.hpp`; `WebGlBufferUtilities` → `buffer_utilities.hpp`; `WebGlShaderUtilities` → `shader_utilities.hpp`; `webgl-program-utilities` → `program_utilities.hpp`; `WebGlTextureUtilities` → `texture_utilities.hpp`; `WebGlSamplerUtilities` → `sampler_utilities.hpp`; `WebGlFrameBufferUtilities` → `framebuffer_utilities.hpp`; `webgl-renderbuffer-utilities` → `renderbuffer_utilities.hpp`; `webgl-blending-utilities` → `blending_utilities.hpp`; `webgl-culling-utilities` → `culling_utilities.hpp`; `webgl-filter-anisotropic-utilities` → `anisotropic_filter_utilities.hpp`; `spector-js-utilities` → `debug_label_utilities.hpp` (KHR_debug object labels instead of Spector metadata); `WebGlUtilities` → `gles_utilities.hpp`.
  - `rendering/webgl-vertex-attribute` and `webgl-vertex-buffer-layout` → `ris/gles/rendering/vertex_attribute.hpp` and `vertex_buffer_layout.hpp`. `buffers/*` → `ris/gles/buffers/` (`GlesVertexBuffer`, `GlesIndexBuffer`, `GlesUniformBuffer`, `GlesBufferFactory`), which implement the abstract buffer classes of `ris/rendering/buffers/`.
  - New: `error_utilities.hpp`, `extension_utilities.hpp`, `ris/utilities/align_utilities.hpp` (`align`, `align_array`) and the enums `TextureFormat`, `SamplerFilter`, `MipMapSamplerFilter`, `SamplerAddressMode`, `SamplerCompareFunction`, `BlendOperation`, `BlendFactor`, `FrontFace`, `ShaderStage`.
  - Not ported: `WebGlGraphicsDevice`, `WebGlRenderer`, swap chain, render pass / pipelines, lights, sampler / shader / texture wrapper classes and gpu info / device features; these need the WebGPU-style object model, which this library does not have (`gfx`, `Texture`, `Shader`, `RenderTarget` fill that role).
  - `graphics.cpp`, `texture.cpp` and the OpenGL ES buffers now call these utilities instead of private GL helpers. Public API, rendered output and the C API are unchanged (the five samples render identical images).
  - Small behaviour differences: GL errors read `OpenGL ES error 0x… in <what>`; out of range enum values throw `Error(Unsupported)` instead of falling back to a default; framebuffer utilities restore the previous framebuffer binding; the `RenderTarget` colour texture uses immutable storage; `glDrawBuffers` is set for more than one colour attachment; `GL_UNPACK_ALIGNMENT` is restored after uploads; anisotropic filtering is implemented (the TypeScript version throws); buffers get a GL object label when `GL_KHR_debug` is available.
